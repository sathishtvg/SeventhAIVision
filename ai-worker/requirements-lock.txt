# Fully-resolved third-party dependency versions for the AI workers, captured
# via `pip freeze` from the docker-ai-worker-intrusion image (built
# 2026-08-06, the most recent of the eleven and the one most recently run).
#
# Why this file exists, concretely rather than in principle: ai-worker/
# pyproject.toml declares only range pins (torch>=2.2, ultralytics>=8.2, ...),
# and the eleven worker images on this host were built between 2026-06-22 and
# 2026-08-06. They have already diverged. Compared on 2026-09-05, the face
# image carries 106 packages and the intrusion image 100, differing in
# aiohttp, anyio, annotated-types, certifi, chardet and more. Eleven workers
# that are meant to be one image are running eleven dependency sets, and a
# model that behaves in one is not guaranteed to behave in another.
#
# Excludes seventh-ai-vision-ai-worker and seventh-ai-vision-shared: both are
# always installed editable from local source (see docker/ai-worker.Dockerfile)
# and never resolved from a registry.
#
# Reproducible install:
#   pip install -r ai-worker/requirements-lock.txt
#   pip install -e shared && pip install -e ai-worker
#
# To refresh after intentionally changing a dependency in pyproject.toml,
# rebuild the image and re-capture:
#   docker compose -f docker/docker-compose.yml build ai-worker-intrusion
#   docker run --rm --entrypoint pip docker-ai-worker-intrusion:latest freeze \
#     | grep -v '^-e ' | grep -v 'Editable install' > ai-worker/requirements-lock.txt
#   (then re-add this header)
#
# NOTE: this is the CPU resolution. docker/ai-worker-gpu.Dockerfile installs
# torch from the CUDA wheel index, so a GPU host resolves a different torch
# build; do not expect this file to pin the GPU image byte-for-byte.
